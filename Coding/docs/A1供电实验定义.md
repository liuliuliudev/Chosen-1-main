# A1第一批：供电调度实验定义

用户确认：概念基准＋设备参数对照；第一批仅供电，第二批再做展帆过程。额外预留比较阴影基础负载的0%、10%、20%，不预先选最优值。Reference目标文件暂不改写，具体文字草案另供确认。

## 对照范围

power_a1组共8案例：650/500 W各1旧调度＋3档新调度。统一电池300 Wh、初始80%、保护20%、原轨道/燃料/固定阴影模型；实际模式负载均由同一工程账本读取：安全等待230 W、推进560 W、帆监测215 W。历史power组继续使用其旧定义，不能用它与新策略直接比较后声称改进全来自控制。

新控制日照中先分配达到下一阴影储能目标所需的充电功率，不用电池在日照中补推进功率；阴影中只允许推进使用基础储备之外的能量。额外储备单位为输出端Wh，考虑充放电效率。若输入功率本身不够，即使停推仍可能缺供，必须保留失败。

控制器固定每60秒决策，并在日照/点火边界立即更新；电池积分可细分到30秒，但不因此改变控制决策频率。首次测试把两者同时减半，500 W时间差约3.76%超标，已记录为失败；修正后应比较相同控制规则的两种计算分辨率。

## 本批验收

1. 每片段发电、负载、充放电损耗与电量变化一致；不透支电池或推进剂。
2. 基础缺供时标power_failure；缺失的到达事件仍为NaN。
3. 比较最低电量、缺供、点火小时、窗口退出、120 km到达时间和燃料，不把“没有缺供”当作硬件认证。
4. 保留0%/10%/20%所有结果；不为改善结果更改电池、负载或时间上限。
5. 展帆继续使用理想瞬时展开，等待/确认/超时草稿未启用、不作为已完成能力。

运行：Coding目录下 `startup; run_power_a1;`，每次生成新a1_时间戳目录。逐片段记录在各案例_power.csv；完整输入与结果在power_a1_results.mat；独立能量审计在energy_audit.csv。
